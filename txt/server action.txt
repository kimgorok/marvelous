# 서버 액션

브라우저에서 호출할 수 있는 서버에서 실행되는 비동기 함수

클라이언트의 브라우저에서 특정 폼에 제출 이벤트가 발생했을 때
서버에서만 실행되는 함수를 브라우저가 직접 호출하면서 데이터까지 formData형식으로 전달하게
해주는 기능
api를 통해서만 진행했어야 하는 브라우저와 서버간의 데이터 통신을 js 함수 하나만으로
쉽고 간결하게 설정할 수 있음

```js
export default function Page() {
    const savename = async (formData: FormData) => {
        "use server"; // 디렉티브 추가

        const name = formData.get("name");
        await sql `INSERT INTO Names (name) VALUES (${name})`; // api 대신
    };

    return (
        <form action={savename}> // 액션 태그
        <input name="name" placeholder="이름을 알려주세요..."/>
        <button type="submit">제출</button>
        </form>
    );
}
```

formData의 get 메서드를 사용하면 브라우저로부터 전달 받은 값을 잘 사용할 수 있음

api를 이용해서 코드를 작성하는 것보다 코드가 간결해짐. 단순한 작업은 서버액션으로 처리 가능

# revalidatePath

revalidatePath 함수가 호출되면 Next 서버가 자동으로 인수로 전달한 경로에 해당하는 페이지를
재검증합니다.

```js
revalidatePath(`/book/${bookId}`);
```

* revalidatePath메서드는 서버측에서만 호출할 수 있는 메서드
revalidatePath메서드는 해당 경로에 해당하는 페이지를 전부 재검증하는 메서드이기 때문에
해당 페이지에 있는 모든 캐시(풀 라우트 캐시 포함)를 강제로 무효화 시킴.

<br />
<hr />

revalidatePath에는 두 번째 인자로 전달할 수 있는 layout과 path 옵션이 있음

1. 특정 주소의 해당하는 페이지만 재검증

```js
revalidatePath(`/book/${bookId}`);
```

2. 특정 경로의 모든 동적 페이지를 재검증
```js
revalidatePath(`/book/[id]`, 'page');
```

3. 특정 레이아웃을 갖는 모든 페이지 재검증
```js
revalidatePath("/(with-searchbar)", "layout");
// 위드 서치바 레이아웃을 갖는 모든 페이지 재검증
```

4. 모든 데이터 재검증
```js
revalidatePath("/", "layout");
```

5. 태그 기준, 데이터 캐시 재검증
```js
// 데이터 페치 부분에 cache 옵션으로 태그 설정
  const response = await fetch(
    `api/review/book/${bookId}`,
    { next: { tags: [`review-${bookId}`] } }
  );

// revalidate 부분에서
revalidateTag(`review-${bookId}`);
```

# useActionState

useActionState훅의 첫 번째 인자로는 action 함수, 두 번째 인자로는 초기값을 보냄

React 19에서 등장한 새로운 훅 :
1. useActionState 
useActionState 훅은 form 태그의 상태를 추적해서, form이 제출될 때 발생하는 비동기 
작업에 따른 상태를 자동으로 업데이트합니다. 
이 훅은 다음과 같은 형태를 가집니다. 

const [상태, 제출함수, is펜딩] = useActionState({비동기 함수}, 상태 기본값); 

먼저 두 번째 요소인 제출함수는 form 태그의 action 속성에 핸들러로 넣습니다. 
이렇게 하여 해당 form이 submit 될 때 제출함수 가 실행 되게 합니다. 
그리고 상태 는 useActionState 의 {비동기 함수} 로 실행한 결과의 값이 들어가게 됩니다. 
{비동기 함수} 실행 전에는 상태 기본값 이 상태 의 초값이 됩니다. 
그리고 이러한 작업이 실행되는 동안 is펜딩 이 true가 되고 작업이 끝나면 is펜딩이 
false가 되어 함수 실행 동안의 조건부 렌더링을 적용할 수 있습니다.

2. useOptimistic 
useOptimistic 훅은 이름에서 알 수 있듯이 낙관적 UI 업데이트를 도와주는 훅입니다. 이 훅은 다음과 같은 형태를 가집니다. 

const [네임, set네임] = useState(’’); const [낙관네임, set낙관네임] = useOptimistic(네임) 

그리고 렌더링 부분에는 네임 이 아닌 낙관네임 을 사용합니다. 이렇게 상태를 선언한 뒤 비동기 작업이 실행되고 성공 시 반환 될 것 같은 값을 set낙관네임 의 인자로 넣습니다. 그리고 실제로 작업이 끝나고 반환 된 값을 set네임 의 인자로 넣습니다. 이렇게 사용하면 사용자는 함수를 실행할 때 즉각적으로 UI의 업데이트를 경험할 수 있습니다.
