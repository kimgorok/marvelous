pre-fetching
사용자가 현재 페이지에서 이동할 가능성이 있는 페이지를 사전에 불러 놓는 기능

next는 번들링을 할 때 현재 페이지에 필요한 JS Bundle만 전달이 됨
만약 모든 페이지의 번들 파일을 전달할 경우 용량이 너무 커지게 되며 Hydration이 늦어짐(TTI가 늦어짐으로 연결)

그렇지만 현재 페이지에 필요한 JS Bundle만 있으면 사용자가 페이지를 이동할 때 마다 Bundle을 받아야 해서
비 효율적인 페이지 이동이 발생할 수 있음. 그렇기 때문에 next에서 pre-fetching 기능을 제공함

> 개발모드에서는 pre-fetching을 확인할 수 없으므로 npm run build 후 npm run start로 production 환경에서 확인가능함

<Link> 컴포넌트로 이루어지지 않은 경로는 pre-fetching이 일어나지 않음
그러므로 router.push같은 프로그래매틱한 페이지 이동에 pre-fetching을 적용하려면
```js
useEffect(()=>{
    router.prefetch('/test');
},[])
```
를 작성해서 화면이 마운트 되었을 때 프로그래매틱 페이지 이동에도 pre-fetching을 적용할 수 있음

// 페이지별 레이아웃 적용하기

특정 페이지에만 레이아웃을 적용하기 위해서 먼저 적용시킬 레이아웃 컴포넌트에 children을 설정하고
```js
export default function OptionalLayout({children}: {children: ReactNode}) {
  return (
    <div>
      <div>특정 페이지 레이아웃</div>
      {children}
    </div>
  );
}
```

적용 시킬 컴포넌트 하단에 다음과 같이 컴포넌트.getLayout를 만든다.
getLayout 메서드는 page라는 매개변수로 page 역할을 할 컴포넌트를 받아와서
별도의 레이아웃으로 감싸진 레이아웃이 적용된 페이지를 return 해줌
Home.getLayout = (page: ReactNode) => {
  return <OptionalLayout>{page}</OptionalLayout>;
};

그리고 최종적으로 루트 디렉토리의 _app.tsx로 가서
export default function App({ Component, pageProps }: AppProps) {
  const getLayout = Component.getLayout ?? ((page: ReactNode) => page);
  return <>{getLayout(<Component {...pageProps} />)}</>;
}
와 같이 getLayout으로 감싸면 사용 가능
